# `production/media/` — Durable Media Artifact Store

**This tree is the canonical durable store for APPROVED ASSET media.**
It is deliberately excluded from the repository's blanket binary `.gitignore` rules. Do not add patterns that re-cover it.

Policy: [`../media-preservation-policy.md`](../media-preservation-policy.md)
Register: [`../media-preservation-register.yaml`](../media-preservation-register.yaml)

## Layout

```
production/media/
└── <case-slug>/                     e.g. case-001
    └── <shot-id>/                   e.g. shot-open-001
        └── <run-id>/                e.g. run-01, run-02
            ├── <asset-id>-master.<ext>        full-sensor / full-resolution master
            └── <asset-id>-crop-185.<ext>      named, deterministic derivative
```

Every derivative carries the master's asset ID plus a derivative suffix, and names the
exact transformation that produced it (e.g. `convert <master> -crop 1403x758+0+130 +repage <out>`),
so any derivative can be regenerated byte-identically from its master.

## Rules

1. **Nothing is deleted or overwritten here.** A superseded medium keeps its file and gains a `SUPERSEDED` `delivery_status` in the register.
2. **A file is not "preserved" until it verifies.** On deposit: record path, SHA-256, byte length, and pixel dimensions; then re-verify the checksum on retrieval.
3. **Approval does not imply availability.** Every register entry states `storage_status` independently of `delivery_status`.
4. **Derivatives are registered, never assumed.** Master, crop, and every deliverable format get their own register entry linked by `derivative_of`.
5. **Test-bench media lives in `verification/tests/**`**, which is likewise un-ignored. Media is promoted from there into this tree only on human approval, and the register records both locations.

## Current backend

Git LFS was the preferred backend. It was tested `2026-10-17` and **failed verification** — the client is not installed and cannot be installed (no root), there is no `.gitattributes`, and the LFS object-storage hosts are firewalled. This in-tree store is the active fallback. See `media-preservation-policy.md` §3.2 for the full test matrix.
